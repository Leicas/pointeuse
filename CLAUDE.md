## Project Overview

Pointeuse is a cross-platform app (Tauri 2 + Rust backend, vanilla JS frontend) for tracking work time against Odoo ERP tasks, on desktop (Windows/Linux/macOS) and Android. It integrates Odoo attendance (check-in/check-out), idle reminders, offline timesheet queuing, and system tray controls.

## Development Commands

```bash
npm install          # Install Node.js dependencies (Tauri CLI + API)
npm run dev          # Start Tauri dev mode (hot-reload frontend, compiles Rust)
npm run build        # Production build (platform-specific installer)
npm run android:init # Generate gen/android/ + apply overlay patches
npm run android:dev  # Run on a connected Android device/emulator
```

Rust-only workflows from `src-tauri/`:
```bash
cargo clippy --all-targets --all-features   # Lint Rust code
cargo check                                  # Fast type-check without building
cargo build                                  # Build Rust backend only
```

There are no automated tests in this project. CI runs clippy, an Android cross-target check, and multi-platform builds.

## Architecture

### Two-layer app

- **Frontend** (`src/`): Vanilla JS with a custom pub-sub store (`main.js` for the timer window, `dashboard.js` for the dashboard window). No build step, no framework. Communicates with backend via `__TAURI__.core.invoke()` commands and Tauri events.
- **Backend** (`src-tauri/src/`): Rust, organized into modules. All shared state lives in `AppState` (Mutex-wrapped fields). Commands are async functions returning `AppResult<T>`.

### Backend module map

| Module | Purpose |
|---|---|
| `lib.rs` | Tauri setup, command registration, background task spawning |
| `state.rs` | `AppState` struct (db, odoo client, timer, reminder, attendance) |
| `error.rs` | `AppError` enum with thiserror, serializes to JSON for frontend |
| `commands/` | Tauri command handlers (auth, timer, tasks, timesheet, attendance, reminder, sync, projects, autostart, analysis) |
| `odoo/` | `OdooClient` + XML-RPC protocol implementation + model structs |
| `timer/` | `TimerEngine` (start/stop/state) + crash-recovery persistence |
| `reminder.rs` | Idle reminder background loop + popup window management |
| `notification.rs` | Android notification system (ongoing timer + reminder channels, `#[cfg(mobile)]`) |
| `tray.rs` | System tray menu with dynamic attendance status |
| `credentials.rs` | System keyring integration for password storage |
| `db/` | SQLite schema migrations, task/project cache, pending timesheets, timesheet log |
| `icon.rs` | Dynamic tray icon generation (procedural P-in-clock-ring; `tools/gen-icon/` regenerates `app-icon.png`: `cargo run --manifest-path tools/gen-icon/Cargo.toml`) |

### Odoo communication

All Odoo interaction uses XML-RPC v2 (`/xmlrpc/2/object` via `execute_kw`). The custom XML-RPC implementation is in `odoo/xmlrpc.rs`. Key Odoo models: `hr.attendance`, `project.task`, `project.project`, `account.analytic.line`. Domain filters use `XmlRpcValue` arrays. Odoo quirk: `false` (not null) represents empty many2one fields.

### Background tasks

Three tokio-spawned loops run at startup (in `lib.rs`):
1. **Attendance poll** — every 60s, syncs attendance status from Odoo, auto-stops timer on external checkout
2. **Idle reminder** — every 30s check cycle, shows popup window when interval threshold is met
3. **Auto-login** — one-shot, restores session from keyring on startup

### Persistence

- **SQLite** (`rusqlite`, bundled): task/project cache, pending timesheets (offline queue), timesheet history, timer crash-recovery state
- **Tauri plugin-store** (`settings.json`): connection details, reminder interval, autostart preference
- **System keyring**: Odoo password only

### Frontend-backend communication

- **Frontend -> Backend**: `invoke('command_name', { params })` (Tauri commands)
- **Backend -> Frontend**: `app_handle.emit("event_name", payload)` for async notifications (attendance changes, timer events, sync status, idle reminders)

### Android

`src-tauri/gen/` is gitignored and regenerated by `tauri android init`. Hand-written Android pieces (manifest with notification/alarm permissions + schedule-task receivers + WorkManager override, custom `MainActivity`, `AppWorkerFactory`, `NotificationActionSetup`, `ScheduledTaskWorkerOverride`) live in `src-tauri/android-overlay/` and are applied on top of the generated tree by `scripts/patch-android-gen.mjs` (run automatically in CI and by `npm run android:init`). The script detects the generated package name and substitutes `__APP_PACKAGE__` in the overlay Kotlin files.

## CI/CD

GitHub Actions: `ci.yml` (clippy + Android cross-check on PRs/pushes) and `release.yml` (semantic-release on `main`/`beta`, then desktop builds via tauri-action with updater artifacts uploaded to GitHub Releases, plus signed Android APK/AAB when keystore secrets are configured). The desktop auto-updater pulls `latest.json` from GitHub Releases.

## Conventions

- Commits follow [Conventional Commits](https://www.conventionalcommits.org/) (required for semantic-release)
- Rust errors go through `AppError` / `AppResult<T>` — never panic in command handlers
- The frontend has no build tooling — UI changes go in `src/main.js` / `src/dashboard.js`
- Main window is 480x680px with custom titlebar (decorations disabled)
